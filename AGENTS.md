# AGENTS.md

Agent guide for openlucky. Architecture detail lives in `CLAUDE.md` — read that first.

## Commands

Always use `just`. Never call `pytest` directly or activate the venv manually.

| Task | Command |
|---|---|
| Run all checks | `just ci` |
| Run tests | `just test` |
| Run a single file | `just test-file <path>` |
| Tests with coverage | `just test-cov` |
| List all targets | `just --list` |

**Run `just ci` before finishing any task.**

## Code standards

- Python 3.12+
- Ruff line length: 100
- New behavior requires tests in the same commit — no exceptions.

## Isolation boundary

`ClaudeCodeAgent` (`agents/claude_code.py`) must stay ignorant of Telegram and the database. Do not pass PTB objects, chat IDs, or DB handles into it. This boundary is load-bearing for testability.

## Secrets

`config/settings.yaml` and `config/settings.dev.yaml` are gitignored. Never commit them. Use the `.example` files as templates.

## MVP scope (v1 limits)

Do not add:
- Multi-user permission system
- Token-by-token streaming
- Parallel sessions
- Complex memory or summarization
- Auto repo discovery

## Visual transcript review

After any change that touches `app/command_router.py`, `app/command_help.py`, or any file under `tests/e2e/`, the transcript HTML artifacts are already generated by `just test-cov`. Submit them as visual artifacts so reviewers can see the conversation flow in the PR's visual review section:

1. Run `just test-e2e` (or confirm `test-cov` already ran and generated `tests/e2e/artifacts/`).
2. Call the `start_preview` MCP tool pointing at `tests/e2e/artifacts/` to start a local HTTP server.
3. For each HTML file in `tests/e2e/artifacts/` (skip `index.html` last, do per-test files first):
   a. `browser_navigate` to the file's URL.
   b. `browser_screenshot` to capture it.
   c. `submit_visual_artifact` with a descriptive label (e.g. `transcript: test_happy_path`).
4. `stop_preview` to clean up the server.

This makes the rendered Telegram-style transcript visible in the PR's visual review section — reviewers can see the user/bot bubble conversation without a local checkout.

Only do this when the change is likely to affect observable bot behavior (new !command, changed reply format, e2e test changes). Skip for pure refactors or unrelated changes.
